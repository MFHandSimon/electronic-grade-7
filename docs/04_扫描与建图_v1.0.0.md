# 04 · 扫描与建图

> 目标：让小车在原地转一圈，每 30° 测一次四方向距离，得到 12 行数据，
> 画成俯视图并拟合出场地长宽。
>
> 前置条件：`02` 四路全 OK、`03` 能发 `T` 收到数据、传感器已微微上仰。

---

## 一、摆场地（很重要）

| 要求 | 原因 |
|---|---|
| 场地是个**矩形**，边长 1.2–1.6m 左右 | 拟合模型假设是矩形；太小传感器量程没意义，太大超量程 |
| 小车放在**场地中心附近** | 拟合算法假设车在中心；放边上对角会到 1.9m，超量程全变 `-1` |
| 车到每面墙的距离 **≤1m** | VL53L0X 实际可靠量程约 1.2m，超过开始大量丢数据 |
| 墙面平整、**颜色浅** | 深色/吸光材质反射弱，读数会偏大甚至丢数 |
| 地面上没有杂物挡光 | 会把点云搅乱 |

**车放角落会怎样**（实测）：对角 1.94m，48 个采样里 7 个 `-1`，拟合出来 1303×884，
完全不可信。所以**必须在中心附近**，误差别超过 20cm。

---

## 二、跑扫描

### 1. 上电、归零

ESP32 上电 → RDK 上执行（车要先摆好位置）

```bash
python3 -c "
import serial,time
s=serial.Serial('/dev/ttyS3',115200,timeout=0.2)
time.sleep(0.2)
s.write(b'E')   # 关流式，免得数据刷屏
s.write(b'Z')   # 航向角归零（这一步必须做！）
time.sleep(0.3)
print('ready')
"
```

> `Z` 不归零会怎样：yaw 从上一次的累计值继续算，扫描脚本按「转到 30°、60°…」判断，
> 起点不是 0 就永远等不到目标角，扫到中途卡死。

### 2. 跑 s360

```bash
python3 /app/s360.py
```

正常输出（12 行，一行一个方向）：

```
0 yaw=30.4 F 892 R 1231 B 610 L 845
1 yaw=60.1 F 1120 R 987 B 705 L 1130
...
11 yaw=361.7 F 573 R 982 B 610 L 845
OK 12 /app/s360_144423.csv
```

**脚本在干什么**（`rdk_scripts/s360.py`）：

1. 发 `E` 关流式、发 `Z` 归零
2. 循环 12 次，目标角度 = 30°、60°…360°
3. 每次发 `D`（右转）转 50ms 然后 `X` 停，反复发 `T` 读 yaw，直到 yaw 到目标值
4. 到位后采一次，把 `yaw, f, r, b, l` 存进列表
5. 收尾发 `X`、`E`，把 12 行写进 `/app/s360_<时分秒>.csv`

### 3. 判断这次扫描是否可信

| 现象 | 判断 |
|---|---|
| 12 行都打印、末尾 `OK 12` | 扫完了，继续 |
| 中途 `FAIL` | 某一步没读到数据，重跑 |
| 最后 yaw 只有 170 左右 | 只转半圈 → 脚本步数写错（12 才对，24 是两圈） |
| 最后 yaw 到 720 左右 | 转了整整两圈，步数写成 24 了 |
| 数据里大量 `-1` 或恒定 200–250 | 传感器在量地面，回 `01` 把镜头侧垫高 |
| 全程距离 <400 | 车贴墙太近或传感器被挡 |

## 三、把数据拿回电脑

```powershell
scp root@<RDK的IP>:/app/s360_144423.csv .
```

（文件名换成你自己的时间戳。没有 scp 就在 RDK 上 `cat` 出来复制粘贴成文件。）

CSV 长这样：

```
yaw,f,r,b,l
30.4,892,1231,610,845
60.1,1120,987,705,1130
...
```

单位都是 mm，`-1` 表示超量程或无效。

## 四、画图

在仓库根目录（有 `plot_scan.py` 的地方）执行：

```bash
python3 plot_scan.py s360_144423.csv                 # 终端字符图，快速看形状
python3 plot_scan.py s360_144423.csv --png out.png   # 出 PNG
```

可选参数：

| 参数 | 作用 |
|---|---|
| `--png 文件名` | 输出 PNG（脚本自己写 PNG，不需要 matplotlib） |
| `--min 300` | 丢掉 300mm 以内的点（清地面假点） |
| `--fr` | 只用前/右两路（当你只有这两路可靠时） |

## 五、拟合矩形

```bash
python3 fit_rect.py s360_144423.csv
python3 fit_rect.py s360_144423.csv --png fit.png
```

输出形如：

```
拟合结果: 1270 x 1480 mm
平均残差: 39.8 mm
点数: 48
```

- **1270 × 1480 mm** 是拟合出的场地长宽
- **平均残差 39.8mm** 是每个测距点离拟合边的平均偏差，**40mm 以内算好结果**
- **点数 48** = 12 行 × 4 个方向（有 `-1` 的会少几个）

> `fit_rect.py` 假设车在中心；`fit_rect2.py` 额外拟合旋转角和车的偏移，车摆得不太正时用后者。

## 六、跟实物对照

拿卷尺量场地实际长宽，和拟合值比：

| 实测 | 拟合 | 误差 |
|---|---|---|
| 1.26 m | 1270 mm | 10 mm |
| 1.48 m | 1480 mm | 0 mm |

**误差 1cm 以内就是这个系统的最好水平**（残差 37–40mm 是常态）。

## 七、已知限制（答辩可以直接讲）

1. **量程限制**：可靠到 1.2m，1.9m 开始丢数据 → 场地不能太大，车不能靠边
2. **单点扫描**：只在一个位置扫，看不到遮挡物后面的墙；要做完整建图得多个站位拼接
3. **航向漂移**：陀螺积分 2.5s 转 887° 对目测 2.4 圈，误差约 2.6%，长时间跑必须配合重定位
4. **俯角敏感**：镜头朝下就全军覆没，必须物理上仰，软件滤不掉
